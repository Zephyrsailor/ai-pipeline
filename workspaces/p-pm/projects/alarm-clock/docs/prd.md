# PRD：Web 闹钟应用（alarm-clock）

- **项目名**：alarm-clock
- **仓库路径**：`/tmp/alarm-clock-app`
- **文档版本**：v1.0
- **语言/技术约束**：纯前端 `HTML + CSS + JavaScript`，无后端

---

## 1. 背景与目标

### 1.1 背景
用户需要一个打开浏览器即可使用的闹钟工具，不依赖后端服务，不需要注册登录，能够完成常见提醒场景（学习、会议、休息、番茄钟等）。

### 1.2 产品目标
构建一个轻量、直观、稳定的 Web 闹钟应用，满足以下核心能力：
1. 支持多个闹钟并可区分用途（时间+标签）
2. 到时有明确提醒（铃声+可视通知）
3. 可一键贪睡，并支持自定义贪睡时长
4. 支持亮色/暗色主题切换
5. 所有功能均在前端实现

### 1.3 成功标准（Success Metrics）
- 用户可在 **1 分钟内**完成第一个闹钟创建。
- 在页面保持打开状态下，闹钟触发提醒成功率达到 **99%+**。
- 主题偏好与贪睡设置在刷新后保持一致。

---

## 2. 目标用户与使用场景

### 2.1 目标用户
- 需要临时提醒的普通用户
- 不希望安装原生 App 的用户
- 需要在桌面浏览器快速设置多个提醒的用户

### 2.2 典型场景
- 上班前设置多个整点提醒
- 学习时设置课程/休息提醒
- 开会前设置预提醒

---

## 3. 范围定义

### 3.1 In Scope（本期范围）
- 多闹钟管理：新增、展示、启用/停用、编辑、删除
- 闹钟字段：时间（HH:mm）+ 标签（文本）
- 闹钟触发：播放铃声 + 页面通知；具备浏览器通知能力（在授权后）
- 贪睡：默认 5 分钟，可配置
- 主题切换：亮色/暗色
- 本地持久化：闹钟数据、主题偏好、贪睡配置

### 3.2 Out of Scope（本期不做）
- 账号体系、登录注册
- 云同步/多端同步
- 后端服务、数据库
- 高级重复规则（如工作日、每周循环）
- 跨设备推送

## 4. 功能需求

### FR-1 多闹钟管理
- 用户可创建多个闹钟。
- 每个闹钟包含：
  - `time`：时间（HH:mm）
  - `label`：标签（用于区分闹钟用途）
  - `enabled`：启用状态
- 支持编辑与删除单个闹钟。
- 支持启用/停用切换。

### FR-2 到时提醒（铃声 + 通知）
- 当本地时间达到闹钟时间且闹钟启用时，触发提醒。
- 提醒包括：
  - 音频铃声播放
  - 页面内可视化通知（弹层/对话框）
- 若浏览器通知权限已授权，则同步发送系统通知。

### FR-3 贪睡（Snooze）
- 闹钟响起时提供“贪睡”按钮。
- 默认贪睡时长为 5 分钟。
- 用户可在设置中修改贪睡时长（建议范围 1–30 分钟，整数）。
- 点击贪睡后，提醒延后到“当前时间 + 贪睡时长”。

### FR-4 主题切换
- 提供亮色/暗色主题切换入口。
- 切换后实时生效，无需刷新页面。
- 主题偏好本地保存，下次进入自动恢复。

### FR-5 纯前端实现
- 使用 HTML/CSS/JS 实现。
- 无后端依赖。
- 本地存储（如 localStorage）用于持久化。

---

## 5. 非功能需求（NFR）

- **兼容性**：Chrome/Edge/Safari/Firefox 近两个主版本可用。
- **易用性**：新增闹钟流程不超过 3 步。
- **性能**：首屏加载后可立即操作；常规交互无明显卡顿。
- **可访问性（基础）**：按钮、输入框具备清晰文案；主题对比度可读。
- **可靠性**：在页面保持激活的情况下，闹钟触发延迟控制在可接受范围（目标 3 秒内）。

## 6. 用户故事（MoSCoW 优先级）

### Must
1. **US-M1**：作为用户，我希望创建多个带时间和标签的闹钟，以便管理不同提醒事项。
2. **US-M2**：作为用户，我希望闹钟到点时能听到铃声并看到通知，以便不遗漏提醒。
3. **US-M3**：作为用户，我希望闹钟响起后可点击贪睡，默认延后 5 分钟且可配置，以便灵活处理当下状态。

### Should
4. **US-S1**：作为用户，我希望能在亮色/暗色主题间切换，以便在不同光照环境下舒适使用。
5. **US-S2**：作为用户，我希望刷新页面后仍保留闹钟与偏好设置，以便减少重复操作。

### Could
6. **US-C1**：作为用户，我希望界面足够简洁，能快速完成核心操作，以便提升日常使用效率。

### Won’t（本期不做）
- **US-W1**：作为用户，我希望通过账号在多设备同步闹钟。
- **US-W2**：作为用户，我希望设置复杂重复规则（工作日/每月）。

## 7. 验收标准（Acceptance Criteria）

### 对应 US-M1（多闹钟管理）
1. 可新增闹钟，保存前需校验时间有效、标签非空。
2. 列表可同时展示多个闹钟（至少 20 条），每条显示时间、标签、启用状态。
3. 支持编辑与删除；删除后该闹钟不再触发。
4. 支持启用/停用，停用状态下到点不触发。

### 对应 US-M2（到时提醒）
5. 到达闹钟时间后 3 秒内触发提醒流程（页面活跃条件下）。
6. 提醒时必须播放铃声并显示页面通知层（包含标签与当前时间）。
7. 若通知权限已授权，则同步弹出系统通知；若未授权，提供一次性引导但不阻塞使用。

### 对应 US-M3（贪睡）
8. 提醒通知层包含“贪睡”按钮。
9. 默认贪睡时长为 5 分钟。
10. 用户可将贪睡时长设置为 1–30 分钟整数。
11. 点击贪睡后，下次提醒时间应为“当前时间 + 贪睡时长”。

### 对应 US-S1（主题切换）
12. 提供亮色/暗色主题切换控件。
13. 主题切换实时生效，无需刷新。
14. 主题偏好可持久化并在刷新后恢复。

### 对应 US-S2（持久化）
15. 闹钟数据（时间、标签、启用状态）刷新后可恢复。
16. 贪睡配置刷新后可恢复。

### 对应 US-C1（体验）
17. 新增闹钟操作路径不超过 3 步。
18. 页面信息层级清晰，核心区域（列表、创建入口、设置入口）可快速定位。

## 8. 风险与注意事项

1. **浏览器后台节流**：标签页在后台时，定时器可能被降频，影响触发精度。
   - 应对：采用时间差校准策略，避免仅依赖固定间隔计时。
2. **通知权限差异**：不同浏览器对通知权限与音频自动播放策略不同。
   - 应对：首次使用引导用户授权，并提供手动测试提醒入口。
3. **音频自动播放限制**：部分浏览器要求用户交互后才可播放声音。
   - 应对：在首次操作时初始化音频上下文并提示测试铃声。
